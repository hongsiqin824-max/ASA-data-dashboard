# iOS / 鸿蒙双平台 ROI 看板设计

## 目标

在不复制整套应用、也不混用平台数据的前提下，为现有 ROI 数据后台增加鸿蒙视图。运营同学可以在 iOS 与鸿蒙之间切换，并继续使用现有的关键词、计划、日期、详情、导出、缓存和刷新流程。

## 产品范围

- 提供 `iOS` 与 `HarmonyOS` 两个相互独立的平台视图，界面上把 `HarmonyOS` 展示为“鸿蒙”。
- 本期不提供跨平台合并视图。
- 保留现有表格布局、ROI 成熟度规则、查询规则和刷新规则；指标按平台真实字段展示。
- iOS 使用现有数据源，鸿蒙使用新表 `ads.ads_ad_hm_roi_di`。
- 鸿蒙字段缺失时，不得使用 iOS 数据、复制值或自行计算的占位数据补齐。鸿蒙没有广告收入和 iOS 安装拆分，界面与导出直接隐藏对应字段。

## 交互设计

在首页筛选栏最前面增加紧凑的平台分段控件：

```text
数据平台  [ iOS | 鸿蒙 ]   日期范围 ... ROI 分层 ... 关键词 ... 查询
```

平台切换属于立即生效的模式切换，不是等待点击查询才生效的普通筛选。切换时：

1. 更新 URL 中的 `platform` 参数。
2. 按现有“缓存优先”路径加载所选平台。
3. 保留日期范围、ROI 分层、收益模式、关键词搜索和当前首页页签。
4. 清空平台专属的计划 ID 和广告组 ID。
5. 详情页通过 URL 绑定平台；用户返回首页后再切换平台。

平台文案不能把鸿蒙数据称为 ASA 数据。左侧导航、页面标题和顶部眉题都要标识当前平台，例如 `iOS 计划 ROI` 和 `鸿蒙计划 ROI`。数据源状态必须显示当前响应来自哪一个平台表。

## 平台模型

前后端共用同一平台类型：

```ts
type DataPlatform = "iOS" | "HarmonyOS";
```

`HarmonyOS` 的界面标签为“鸿蒙”。为兼容旧链接，没有 `platform` 参数的 URL 默认使用 iOS。非法平台值返回 HTTP 400，且绝不能参与 SQL 表名拼接。

## 数据源隔离

后端维护固定白名单映射：

```text
iOS       -> hive.ads.ads_ad_ios_asa_roi_di
HarmonyOS -> hive.ads.ads_ad_hm_roi_di
```

鸿蒙完整限定名已通过 StarRocks 只读连接确认是 `hive.ads.ads_ad_hm_roi_di`。表名只能由后端解析，HTTP 请求不能直接传入表名。

以下所有查询都必须显式接收解析后的平台数据源：

- 看板汇总；
- 历史首投日和末投日；
- 数仓截至日；
- 日期汇总；
- 关键词每日明细；
- 广告组筛选；
- SQL 查看元数据。

接口响应必须携带当前平台，让前端核对响应平台与请求平台是否一致。

## 已确认的鸿蒙表结构

鸿蒙表不是 iOS ASA 字段的同构版本，真实粒度为：

```text
day + task_id + sub_task_id
```

平台适配层只做可信字段映射：

```text
task_id / task_name       -> 任务 ID / 任务名
sub_task_id               -> 子任务 ID
exposure / click          -> 展示 / 点击
download                  -> 下载
new_user_cnt              -> 激活
new_register_cnt          -> 注册
revenue_vip_*             -> 会员收入
revenue_charge_*          -> 充值收入
revenue_* / spend         -> 汇总 ROI 的成本加权口径
```

源表没有子任务名，所以不能把 `task_name` 重复当成子任务名；子任务入口展示真实 `sub_task_id`。源表没有广告收入、点击安装、新下载和重下载拆分，因此鸿蒙 UI 与 CSV 不展示这些列。

## 表结构准入检查

启用鸿蒙前，必须比较两张表中 `server/starrocks.ts` 实际使用的全部字段。

- 日期、计划、广告组、关键词、成本，以及约定收益和 ROI 计算所需字段必须存在。
- 字段类型差异必须人工确认，不能静默转换后直接上线。
- 缺失的可选指标不能作为业务数据展示。内部统一查询层为兼容共用聚合 SQL 保留的占位列，不得出现在鸿蒙 UI、导出或文案中。
- 鸿蒙请求的任何前端或后端降级逻辑都不能读取 iOS 表。

## API 与缓存规则

看板、每日明细和 SQL 元数据接口都要解析并校验 `platform`。平台必须进入：

- 服务端看板缓存键；
- 浏览器看板缓存键；
- 每日明细请求标识；
- 日期关键词作用域标识；
- 导出文件名和元数据。

浏览器缓存版本需要升级，避免旧的 iOS 单平台响应被当成双平台响应。服务端缓存必须加入平台，防止同一日期和筛选条件下 iOS 与鸿蒙共用数据。

查询和刷新语义保持不变：

- `查询`：只读取所选平台缓存；缓存未命中时返回空结果并提示点击刷新。
- `刷新`：绕过并覆盖所选平台缓存，不影响另一个平台。

默认近 7 天缓存分别预热 iOS 和鸿蒙，按顺序执行并隔离错误，任何一个平台失败都不能阻断另一个平台。

## 前端改动

- 在 `FilterBar` 增加平台分段控件。
- 把 `KeywordRow.platform` 等相关类型统一为 `DataPlatform`。
- 页面、侧边栏、数据源状态、空状态和导出文案跟随平台。
- 继续复用现有表格组件，不复制 iOS 与鸿蒙两个版本。
- ROI 成熟度继续根据所选数据源的历史首投日和数仓截至日判断。
- 详情加载作用域加入平台，避免切换或导航时复用另一个平台的每日数据。

## 错误处理

- 非法平台：返回 HTTP 400 和明确的校验提示。
- 数据表不存在或不可访问：错误信息要指明所选平台，同时保留页面上已有数据。
- 表结构不兼容：鸿蒙准入检查失败，不部署可见的鸿蒙入口。
- 单个平台预热失败：记录平台错误并继续预热另一个平台。
- 查询区间无数据：展示现有空状态并说明所选平台数据源，不回退到另一个平台。

## 验证要求

### 数据验证

- 比较 iOS 和鸿蒙表结构及字段类型。
- 记录两个数据源的最早日期、最新日期和总行数。
- 两个平台各选一个代表日期及关键词或计划，直接对比 StarRocks 聚合与 API 的成本、广告收入、付费收入、总收益、总 ROI 和 D1-D30。
- 确认未成熟 ROI 窗口继续为空。

### 隔离验证

- 用相同日期筛选分别查询 iOS 和鸿蒙，确认数据源元数据和缓存键不同。
- 按 iOS、鸿蒙、iOS 的顺序查询，确认最后一次 iOS 仍是原 iOS 响应。
- 刷新鸿蒙后，iOS 缓存时间和数值不能变化。
- 分别打开两个平台的每日明细和详情页，确认没有跨平台复用数据行。

### 应用验证

- 运行测试、Lint 和生产构建。
- 测试不带平台、`platform=iOS`、`platform=HarmonyOS` 和非法平台的直接链接。
- 在桌面浏览器检查平台控件、URL 持久化、数据源标签、页面标题、空状态和导出文件名。
- 回归既有 iOS 样本，确认 ROI 数值和成熟度规则没有变化。

## 2026-07-18 验证结果

- iOS：133 列、158,493 行，数据范围 `20260616-20260717`，结构准入通过。
- 鸿蒙：103 列、35 行，数据范围 `20260712-20260716`，结构准入通过。
- 鸿蒙共有 7 个任务、7 个子任务；`day + task_id + sub_task_id` 无重复，核心身份字段无空值。
- 35 条记录的会员加充值收入等于总收入；总 ROI、D1-D7、D15、D30 全部与对应收益除以花费一致。
- 鸿蒙 `2026-07-12` 至 `2026-07-16` API 汇总与数仓一致：花费 `21643.98`、总收益 `23272`、总 ROI `107.52%`。
- iOS 与鸿蒙缓存、响应平台、数据表和查询结果已验证互不串用。
- 自动化测试、Lint、生产构建与双平台结构检查通过；浏览器视觉验收待具备可用的 Codex 浏览器运行时后补做。

## 部署规则

沿用现有流程：服务器备份、源码同步、服务器构建、pm2 重启、健康检查、资源检查和生产真实数据验证。不得覆盖服务器环境文件。只有生产鸿蒙表名和表结构准入检查通过后，才部署可见的鸿蒙入口。

## 本期不做

- iOS 与鸿蒙合并汇总。
- 跨平台计划或关键词身份合并。
- 平台对比图表。
- 修改收益定义或 ROI 公式。
- 自动刷新。
